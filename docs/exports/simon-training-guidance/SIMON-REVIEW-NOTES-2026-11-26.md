## Main pack (`00`)

1. **Conceptualisation too open-ended** — define the base formulation explicitly (problem, cause/context, rules/assumptions, belief strength, and linked response).
2. **Reply shape** — clearer turn template: Sentence 1 validate feelings + reflect their language; Sentence 2 connect to the map/loop; then one question.
3. **“Never repeat question”** — often the user *did* answer in their own way; model must accept that answer and advance, not re-ask because the form was unexpected.
4. **Downward-arrow first** — do not jump from a surface thought (e.g. “Who am I to evaluate him?”) straight to body feelings; Socratic deepen first.

## Phase One (`01` + NOTES docx)

**Two Pillars for Phase 1.2 — Cognitive Drivers vs Response Engine**

| Pillar A — Cognitive Driver | Pillar B — Response Outcome |
|-----------------------------|-----------------------------|
| Feared scenario / trigger | Primary emotion (dread, shame…) |
| Automatic hot thought | Avoidance / safety behaviour (e.g. scrolling) |
| Demanding rule / assumption | Somatic sensation (chest, knot…) |
| Belief strength 0–100% | Response intensity / distress 0–100% |

**Maintenance loop (must socialise before Handshake):**

1. Cognitive trigger → somatic/emotional surge  
2. Emotional surge → coping / safety behaviour  
3. Coping → short-term relief + secondary guilt + rule never tested → belief stays locked high  

Example sum-up: “When I look at the file, my Rule (100%) triggers intense Dread, which forces me to Scroll, temporarily relieving panic but reinforcing that I can’t handle the task.”

## Phase Two (`02`)

1. **Goal lock sequence:** affirm map → ask what a goal toward getting past the problem would be → “If we get to this goal, what would it mean for you?” → dedication rating 0–100 → then lock in writing.
2. **Micros per step:** minimum **2**, maximum **4** (was “at most 2”).
3. **Stimulus control** — spell out in plain language (e.g. phone away, timer) — Simon flagged “not sure what this means.”
4. **HCPR / DTR** — belongs on the **Sustainability Path (Phase Three)** when the user cannot activate / proceed with a Phase Two step — not dumped during ladder build.
5. **Confidence &lt;7:** do not only shrink silently — ask why it is below 7, what makes it that, and what we can change to raise it (reassess goal / step / micro).
